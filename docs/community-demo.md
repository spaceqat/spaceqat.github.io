# 会员中心与论坛 Demo

入口：`community-demo.html`。沿用现有静态服务预览，无需构建。

本 Demo 使用虚构人物、帖子、贡献统计与 Badge；浏览器 localStorage 的 `spaceqat-community-demo-v1` 保存体验数据。页面顶部持续显示演示状态。它不执行真实注册、发邮件、Notion 同步、积分计算或发证。不能将这里的身份切换或客户端状态用于生产鉴权。

## 体验路径

1. 我的空间：查看示例贡献、升级缺口，编辑资料与公开偏好，选择最多三枚已获得徽章。
2. 徽章收藏：查看 L0–L5、四路线铜银金、12枚成就与校园大使身份；点击查看条件。
3. 社区论坛：分类、搜索、查看作者公开主页与徽章。
4. 发布帖子或回复：保存草稿或提交审核；待审内容只出现在我的投稿及审核队列。
5. 审核工作台：显式进入演示审核员身份，退回并填写意见，或通过发布。
6. 已发布帖修改：新版本进入审核，旧内容保持公开；通过后替换。
7. 页面顶部可重置本浏览器演示数据。

## 后续生产接入

采用认证服务与数据库管理用户、Profile、帖子、帖子版本、回复、审核记录、积分账本和 Badge 授予。服务端强制所有者权限、发布状态、审核岗位与回避规则；客户端不可修改积分、Badge 或审核状态。Notion 保留规则维护及审核入口，可信服务端验证审核结果并幂等同步。

正式接入前需要创建后端项目，配置邮箱验证与发送域名、公开网址及登录回调、Notion integration 权限与服务端密钥。密钥不得写进静态仓库。上线前验证游客不能读取待审内容、作者不能自批、旧版本审核不能覆盖新版本、撤销授权及时生效、同步重试不会重复计分。

当前统计是展示数据，不是从三条“最近贡献”推算的完整积分账本；Badge 条件来自校园网络 V1.0 建议试行手册。生产环境需同时核对等级门槛、自然周覆盖、成果根 ID、路线和近期积分、独立使用证据及人工评审。
