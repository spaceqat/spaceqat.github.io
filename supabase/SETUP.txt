SpaceQat 真实账号接入与数据库配置

Mini grant 申请（014_mini_grants.sql）：
执行后创建私有 mini-grant-proposals 桶（PDF，最大 10 MB）及申请表。
只有真实获得 L3/L4/L5 徽章的会员可提交；申请金额 >0 且 <=3000 元。
申请人及管理员可读取申请；普通审核员、其他会员和匿名用户不可读取材料。
本人入口：我的空间 → Mini grant；管理员入口：迷你基金申请。
Proposal 声明 2–4 页 A4、10/11 pt，包含动机、意义、执行方式及里程碑。
声明由评审人工核验，不等同于自动检测 PDF 排版。PDF 下载链接有效期 60 秒。
当前功能负责收件与私密下载；专家评审、最终金额确认及拨款在线下处理。
提交后更正或撤回请联系社区；没有自动授予积分、徽章或付款操作。
未提交成功的孤立上传由管理员定期核对清理；已提交文件不允许会员直接删除或覆盖。

1. Supabase SQL Editor → New query，粘贴 001_members.sql 全文并 Run。
   此脚本只运行一次。表名 member_profiles，不覆盖其他已有表。
   包含 RLS：用户只可读取自己的资料，只可修改 display_name / bio；
   不允许客户端创建资料、删资料、改 id、积分或创建时间。
   触发器随注册创建零积分资料；不会导入 Demo 用户、积分或权限。

2. Authentication → URL Configuration：
   Site URL: https://space-qat.com/account.html
   Redirect URLs 添加以下精确地址（不要使用全站通配符）：
   https://space-qat.com/account.html
   https://space-qat.com/account.html?lang=en
   http://127.0.0.1:8765/account.html
   http://127.0.0.1:8765/account.html?lang=en
   上线后如不再需要本地测试，移除本地地址。

3. Authentication 邮箱认证：允许 Email 注册、开启 Confirm Email；
   换绑邮箱：在 Email provider 设置中保持 Secure email change 开启，要求新旧邮箱确认。
   Change Email Address 邮件模板保留官方 ConfirmationURL；不要关闭安全验证来简化流程。
   前端入口为“我的空间 → 账号安全 · 更换邮箱”，使用 auth.updateUser，不创建新用户。
   用专用测试邮箱验收双邮箱确认、旧链接过期、占用邮箱、限流及刷新后登录邮箱更新；
   此流程不修改会员 ID、徽章、帖子和关注关系，不能用管理员改邮箱接口替代本人验证。
   密码长度至少 12 位，服务端设置也必须同步；不启用匿名登录。
   验证和恢复邮件模板保留官方 ConfirmationURL，不填入首页链接。

4. 配置 Custom SMTP 才能面向公众发邮件。
   默认邮件服务仅允许项目团队邮箱，官方限制为每小时 2 封，不适合生产。
   SMTP 密码只在控制台填写，绝不能提交到 Git 或前端。
   验证发信域名 SPF/DKIM/DMARC，并测试常用邮箱收件及垃圾邮件。
   上线前设置服务端限流；若启用 CAPTCHA，需先在前端添加组件与 captchaToken，
   当前页面尚未接入 CAPTCHA，不能仅在控制台开启后直接发布。

5. 本地访问 account.html#signup（英文 account.html?lang=en#signup）。
   用自己控制的邮箱测试注册 → 验证 → 登录 → 修改资料 → 刷新 → 退出。
   测试重发验证邮件、密码恢复、新密码登录、旧密码失效、过期链接提示。
   浏览器前端使用固定版本 supabase-js SDK，密码仅发送给 Supabase Auth。
   SDK 会在本浏览器保存会话，不保存明文密码。不同域名不共享会话。

6. 上线验收：用两个测试账号确认 A 不能读改 B，不能改积分；游客无资料访问。
   数据库脚本未执行前，注册可能创建 Auth 用户，但资料页会提示尚未就绪。
   不可将前端测试/mock 视为数据库安全测试已通过。
   徽章与论坛接入见下文第二阶段。Notion 同步、自动贡献计分、账户删除界面尚未实现。
   Demo 保留在 community-demo.html，与正式账号完全分离。
   公开发布前还需确认隐私告知与数据删除联系流程。

参考：https://supabase.com/docs/guides/auth/managing-user-data
参考：https://supabase.com/docs/guides/auth/auth-smtp

第二阶段：徽章与论坛

在 001_members.sql 已成功执行的项目中，仅执行一次 002_community.sql。
它新增 31 枚徽章目录、徽章授予表、投稿表和审核员表；保留现有会员资料。
徽章按已确认的贡献授予，不根据注册或积分猜测授予；空账号显示未点亮。
个人资料和邮箱仍仅对本人可见。论坛只返回已发布帖子、作者昵称和徽章。
普通会员不能直接写入帖子表，执行 003_category_publication.sql 后，提交 RPC 按分区决定发布或审核，并限制 30 秒间隔、每小时 5 篇。
用户不能直接改审核状态、授予徽章或修改审核员名单。审核员不能审核自己的帖子。
当前版本支持文字发帖及审核；回复、附件、帖子修改和自动贡献积分不在此版本。

在 SQL Editor 为指定人员赋予审核权限（先将占位邮箱替换成你确认的审核员邮箱）：
insert into public.community_moderators(user_id)
select id from auth.users where email='REPLACE_WITH_REVIEWER_EMAIL'
on conflict do nothing;

只有存在审核角色的账号才能在论坛看到“审核投稿”入口。
通过 Database Table Editor / SQL Editor 人工核验后向 member_badges 插入 user_id 和 badge_id，即可点亮对应徽章。
删除该授予记录会撤销徽章；前端没有自助授予权限。
执行后用两个账号测试：知识与作品、社区公告的待审核帖子仅作者和审核员可见；其他三个分区立即进入论坛。
拒绝理由仅作者和审核员可见。自动积分升级尚未实现，需要按实施手册核验后管理。

第三阶段：按分区发布
在 002_community.sql 已执行后，运行 003_category_publication.sql（可以重复运行）。
提问与互助、FatQat 开源、校园交流的新帖直接发布；知识与作品、社区公告的新帖进入审核。
仅更新发布函数，保留原有数据；历史待审核投稿仍需审核，不会批量公开。
发布状态由服务端决定，前端读取实际结果；30 秒间隔和每小时 5 篇限制继续生效。

第四阶段：管理员与 GitHub 贡献
详细配置见 GITHUB_SETUP.txt。依次运行 004_github_contributions.sql、005_bootstrap_admin.sql。
005 的首位管理员使用用户明确指定的邮箱；本机已填好 bootstrap-admin.local.sql（不提交到 Git）。
绑定 GitHub、部署 Edge Function 和启用定时补查需要额外配置，单独推送网页不会自动完成。
